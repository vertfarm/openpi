# HV1 9/10 재수집 → C-5000 추가 학습 → 오후 비교

> **기록 전용 (2026-09-11).** `readapt_*` 모듈은 삭제했으므로 아래 명령은 더 이상
> 실행되지 않는다. 이 문서는 N/M 캠페인에서 무엇을 돌렸는지에 대한 기록이며,
> 현재 운영 절차는 [TWO_TRACK_20260910.md](TWO_TRACK_20260910.md)를 따른다.
> 코드가 필요하면 `git show 3676ccb:examples/hv1/readapt.py`로 꺼낸다.

이 도구는 ROS/recorder를 교체하거나 로봇을 움직이지 않는다. 현장에서 수집·영상 검수한
별도 세션을 입력으로 받아 N/M을 준비한다. 코드 준비와 실제 학습 완료를 구분한다.

## 현장 수집 카드

- **설정 최종 적용 → 준비용 3회(학습 제외) → 성공 40회**. 코드·교정·카메라 변경 시 새 세션.
- 오른팔 / 은색 실린더 / 책상→고정 트레이. 기준·앞·뒤·좌·우 약 2cm, 위치별 8회.
  표시 위치는 현장 검증 작업영역 안에서만 사용한다. 순서는 `collection_schedule.json`에 있다.
- 기존 dke → upper/dbc 및 시작 자세 절차는 담당자가 실행한다. 이 도구는 실행하지 않는다.
- pose 3 왼팔 조망 자세, head/hand_l/hand_r 유지. mode 2, wrap close, narrow 0.6 release.
- REC 웜업 1초가 끝난 다음 작업. 파지 확인 → 이동 → 안착 → 열기 → 손 이탈까지 녹화.
  해제 뒤 최소 2초의 증거를 보존한다. 시간 늘리기 위한 정지는 하지 않는다.
- 실패·떨림·충돌·수동 개입은 원본을 삭제하지 않고 `exclude`로 표시한다.
- 물리 E-stop 존재는 확인됐다. 정지 시 팔/손 거동·복귀 후 자동 재개 없음은 현장 검증 대상이다.
  직접 joint stream에는 새 자세 이동용 ramp가 자동 적용되지 않는다.

## 실행 환경과 경로

현장 host `~/workspace/openpi-hv1`, ML `.venv`, 기존 branch를 사용한다.
ROS 컨테이너/기존 kh_ws는 수정하지 않는다. 코드 변경은 이 디렉터리와 검증된
모델을 받는 `deploy_server.py`의 선택 경로에 한정한다.

아래는 **host ML 터미널**에서 실행하는 명령이다. `NEW_RAW`는 문종술 선임이 별도
세션으로 저장한 실제 디렉터리로 지정한다. 어제 폴더에 이어 저장하지 않는다.
`SESSION`, `SCAN`, `CAMPAIGN` 출력은 매번 새 경로를 사용하고 템플릿의 승인값은
현장 증거 없이 채우지 않는다. 미완료 campaign을 새 폴더로 우회해 중복 실행하지 않는다.

```bash
cd ~/workspace/openpi-hv1
PARENT=~/workspace/hv1-vla-runtime/overnight-20260909
READY=~/workspace/hv1-vla-runtime/readapt-ready-20260910
CAMPAIGN=~/workspace/hv1-vla-runtime/readapt-20260910

# 최종 소스 적용 후 실행. 파일 캡처만으로 실행 파라미터 적용을 증명하지 않는다.
.venv/bin/python -B -m examples.hv1.readapt capture-session \
  --ros-root ~/workspace/keti_humanoid_ros2 --output "$READY/session_capture.json"
.venv/bin/python -B -m examples.hv1.readapt schedule --output "$READY/collection_schedule.json"
.venv/bin/python -B -m examples.hv1.readapt old-review-template \
  --parent "$PARENT" --output "$READY/old_review.template.json"
```

수집이 끝나면 `NEW_RAW`를 지정하고 다음 명령을 실행한다. 이 명령은 원본을 읽기만 한다.

```bash
.venv/bin/python -B -m examples.hv1.readapt scan \
  --raw "$NEW_RAW" --capture "$READY/session_capture.json" --output "$READY/scan"
```

`scan/review.template.json`을 별도 `review.json`으로, `old_review.template.json`을
`old_review.json`으로 저장하여 검수 결과를 작성한다. reviewer는 내부 식별자만 사용한다.

- 공통: 적용 시각·수집 시작 시각(시간대 포함), 실행 파라미터 근거, 코드 고정·실물 불변 확인.
- 각 episode: `kind=diagnostic/success/exclude`, placement=`center/front/back/left/right`.
  success는 영상 성공·개입 없음·떨림/충돌 없음·명령/실제 전환 검수를 모두 확인한다.
- 어제: A의 19개 중 영상·명령 연속성 재검수를 통과한 것만 approved. 검증 6개는 학습에 넣지 않는다.
- 오늘 첫 `episode_000000/000001`은 자동 더미 취급하지 않는다. identity는 `session::episode`다.
- 어제 의심 4개와 000033은 자동 편입하지 않는다. 숫자 기록은 영상 성공을 대신하지 않는다.

```bash
.venv/bin/python -B -m examples.hv1.readapt prepare \
  --scan "$READY/scan/scan.json" --review "$READY/review.json" \
  --old-review "$READY/old_review.json" --parent "$PARENT" --output "$CAMPAIGN"
.venv/bin/python -B -m examples.hv1.readapt export --campaign "$CAMPAIGN"
.venv/bin/python -B -m examples.hv1.readapt normalization --campaign "$CAMPAIGN"
```

prepare는 40개 성공·5개 배치×8개·준비 3회·모든 검수·원본 hash가 맞아야 통과한다.
오늘 32/8 층화 분할은 seed 42로 고정된다. export는 새 학습+어제 허용 학습을 한 번만
직렬화하고 실제 추출은 실험별 sampler로 제어한다. 검증은 오늘 8개·어제 6개를 분리 보고한다.

`normalization_report.json`의 새/기존 세션별 범위·경계 집중도와 단위/부호/영점을
검수한 뒤 `normalization_review.template.json`을 `normalization_review.json`으로
별도 저장해 승인한다. C-5000 통계는 재계산하거나 덮어쓰지 않는다.

## N/M 학습 계약

| 항목 | 설정 |
|---|---|
| 초기 가중치 | 둘 다 C-5000 BF16에서 FP32 학습 파라미터로 로드, 새 optimizer |
| N | 오늘 학습 관측 100% 추가 학습. 초기 가중치의 어제 학습 이력은 남는다 |
| M | 오늘 80% / 어제 승인 20%, 파일 수가 아닌 추출 관측 수 |
| 추출 | 에피소드 균등, 전체 70% / close ±1초 15% / release ±1초 15% |
| 공통 | full JAX, batch 2, seed 42, horizon 15, EMA 없음, 3-view 유지 |
| LR | 1e-5 peak, warmup 100, cosine 5000, 끝 1e-6 |
| 시점 | 추가 +2000 / +5000, N/M 합계 4개 추론본 |
| 정상 종료 외 중단 | 최신 전체 상태와 정확한 추출 cursor로 명시적 resume |

sampler는 100개 단위에서 비율이 정확히 맞으며 episode 길이에 비례하지 않는다.
관측 시작점만 재추출한다. 실제 15-frame action chunk, 영상 순서, 30Hz 시간축을 바꾸지 않는다.
`sampler_*.json`은 전체 계획, `sampler_cursor_*.json`은 저장된 update와 대응하는 소비 위치다.

기존 C 추론 서버가 같은 GPU lock을 보유한 동안 실행기는 실패 후 대기한다.
**서버/ROS를 자동 종료하지 않는다.** 담당자가 기존 무송신 서버만 정리한 뒤 학습한다.

```bash
# 실제 실행할 때 미래의 현장 마감 시각을 지정한다.
.venv/bin/python -B -m examples.hv1.readapt_run \
  --campaign "$CAMPAIGN" --deadline '2026-09-10T17:00:00+09:00' \
  --reviewer 'field-reviewer' --allow-gpu-run
```

순서는 C-5000의 오늘/어제 검증 → 50-update smoke 및 restart/BF16 일치 확인 →
N 학습·2개 평가/등록 → M 학습·2개 평가/등록 → 비교표다. 네트워크 종료에 견디는
현장 터미널에서 실행하되, 단순히 이 문서를 열었다고 예약·자동 실행되지 않는다.

중단 후 같은 명령은 완료 단계를 건너뛰고 현재 run을 명시적 resume로 이어 간다.
개별 실행도 가능하다:

```bash
.venv/bin/python -B -m examples.hv1.readapt_train --campaign "$CAMPAIGN" \
  --experiment N --deadline '2026-09-10T17:00:00+09:00' --allow-gpu-run --resume
```

전체 restart는 완료·GPU 재로딩 검증 후 이번 campaign의 해당 run만 정리한다.
정리한 run의 정확한 optimizer resume는 불가하며 감사 JSON을 남긴다. smoke 임시 추론본도
동등성 확인 후 정리해 본학습 추론본 4개를 남긴다. 기존 16개 추론본과 원본은 삭제하지 않는다.
원본 처리 중이나 저장 peak에 50GiB 여유가 깨지면 중단한다.

## 평가·배포 연결

평가는 기록 관측을 3-frame 간격으로 넣고 예측 prefix 3을 연결한다. 전체 프레임과
전환 ±1초를 분리해 관절 오차·급변·그리퍼 누락/조기/지연/반복 전환을 보고한다.
실제 closed-loop가 아니며 영상 성공률도 아니다. 오늘/어제 검증 결과를 평균으로 합치지 않는다.

`checkpoint_registry.json`은 평가 파일·가중치·통계 hash를 묶은 **SHADOW_ONLY** 목록이다.
등록은 물리 안전 합격·모델 성능 합격·자동 ARM을 의미하지 않는다.

```bash
.venv/bin/python -B -m examples.hv1.deploy_server --campaign "$CAMPAIGN" \
  --snapshot "$CAMPAIGN/snapshots/N/step_005000" \
  --registry "$CAMPAIGN/checkpoint_registry.json"
```

N을 자동 최종 후보로 고르지 않는다. `candidate_comparison.json`의 오늘 데이터 지표와
물리 gate를 확인한다. denoise 10/prefix 3/30Hz, 기존 ROS 어댑터·정지·제어권·속도·급변
제한은 유지한다. 현장 stop/독립 guardian이 준비되지 않으면 shadow까지만 진행한다.

실기 준비가 되면 동일 5개 배치×각 2회, 후보 순서를 번갈아 비교한다.
손 이탈 후 물체가 트레이에 남는 것을 성공으로 세고, 개입·비상정지는 별도 실패다.
목표 8/10 이상·위험한 급변/충돌 0은 파일럿 목표이지 신뢰성 인증이 아니다.

## 상태와 한계

- `readapt status --campaign ...`는 조회 전용이며 학습을 시작하지 않는다.
- 코드 테스트/합성 데이터 검증과 실물 40개 검수/실제 GPU 학습을 구분한다.
- 현재 collector는 recorder-row 시각 기준이다. 센서 노출 동기화가 증명된 것은 아니다.
- 현장 파라미터/물리 변경 확인은 담당자 증거가 필요하다. 파일 hash로 대신 승인하지 않는다.
- 비교 실행기 실패 로그는 `logs/`, 진행은 `status.json`, run별 결과·cursor는 `runs/`에 있다.
